# Dependencies

Exact source revisions are in [DEPENDENCIES.json](DEPENDENCIES.json). The
GDCubism 0.9.1 merge commit and v0.9.1 tag have identical trees; history is retained.
Production builds must use the pinned Redot binding and a single-precision API
dump generated by the matching Redot editor. Godot binaries are not certified.

The user downloaded Native SDK 5-r.5 from Live2D's official website after accepting
its agreements. The archive, Core header, Linux x86_64 libraries, Windows x86_64
VS 2022 static libraries, and Windows dynamic DLL/import-library pair are
fingerprinted in `DEPENDENCIES.json`; loaded Core reports 6.0.1. Build, install
and CI scripts do not download Core. Library
hash keys are paths relative to `Core`, such as
`lib/linux/x86_64/libLive2DCubismCore.a`. Keep private paths and fixture permission
records outside public source.

Windows source builds use the CRT-matched static Core by default. The
`windows_core_link=dynamic` release path instead links the pinned
`dll/windows/x86_64/Live2DCubismCore.lib`. Its installer accepts only the matching
`Live2DCubismCore.dll` hash from a user-supplied SDK and places it beside the
addon binaries. Neither file belongs in public source or release archives.

`SConstruct` now requires `CUBISM_SDK_ROOT`, the pinned `REDOT_CPP_ROOT` checkout
(defaults to the historical `godot-cpp` submodule path), and `custom_api_file`
from `tools/verify_dependencies.py`. `CUBISM_FRAMEWORK_ROOT` defaults to the SDK's
`Framework` directory. Source filenames and bytes below Framework's `src` are
hashed in sorted POSIX-path order; use unchanged files and LF checkout endings.
The source hash was measured from the pinned public Framework commit, not a
proprietary package. The downloaded SDK Framework independently matches that hash.

`CUBISM_BUILD_DIR` selects object, generated-document and SCons metadata storage.
On hosts whose shared filesystem rejects atomic metadata updates, put this
directory on a normal local filesystem. The addon library retains its upstream
destination under `demo/addons/gd_cubism/bin`.

The optional `build_profile=tools/native_build_profile.json` includes the engine
classes used by this addon and by the pinned binding's support code. The build
adds the profile as a binding-generator dependency, so changing it regenerates
the API wrappers. Use the same profile for debug and release and run builds
sequentially when they share a binding checkout. Linux rejects unresolved symbols
at link time. Windows currently requires VS 2022 (`MSVC_VERSION=14.3`), x86_64,
and SDK toolset directory `143`; Core's MT, MD or MDd library follows the binding's
`use_static_cpp` and `debug_crt` flags. Windows builds and scoped execution checks
have passed; full release qualification remains open. The platform build guides
and [current status](docs/current-status.md) record the actual tested toolchains
and source revisions separately from historical toolchain entries in the pins.

Example Linux build after configuring the local SDK and matching editor:

```sh
export REDOT_CPP_ROOT=/path/to/pinned/redot-cpp
export CUBISM_SDK_ROOT=/path/to/CubismSdkForNative-5-r.5
python -m SCons -j4 platform=linux arch=x86_64 target=template_debug \
  precision=single custom_api_file=/path/to/verified/extension_api.json \
  build_profile=tools/native_build_profile.json
```

Linux and Windows are the planned targets. Build and test results, rather than
this list, determine support. See [implementation status](docs/gamedev/implementation-plan.md).
